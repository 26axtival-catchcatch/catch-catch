B. 브리핑

서비스가 매일 아침 말을 건다

현행 (지금 시안)

날짜 + 한 문장이 화면 절반, 시그널을 한 장씩 넘겨 소비. 진입점은 맨 아래 링크 한 줄.

문제

  • “직접 지켜볼 시그널 걸기”가 눈에 안 띈다
  • 칩을 무한정 늘릴 수 없다
  • 2장 넘기면 할 일이 사라진다
진입점 약함칩 확장 한계

B1. 대화형 마무리

1-a + 2-a + 3-b

  • 카드 액션에 “비슷한 걸 더 찾기” 추가 — 시선이 이미 가 있는 자리
  • 2장을 넘기면 3번째 빈 케이스가 나온다. 칩도 1 · 2 · ⊕로 확장
  • 누르면 화면 전환 없이 아래에 대화가 이어붙는다

노리는 것

브리핑 리듬을 안 깨면서, 다 읽은 시점(행동 준비가 가장 된 때)에 진입점을 놓는다. 칩 확장 한계도 같이 풀린다.

약점

2장을 다 넘겨야 마지막 카드에 도달한다. 그래서 카드 액션 버튼을 보조로 함께 둔다.

톤 유지 최상칩 문제 해결도달까지 2단계

B2. 요청 루프

4-b + 1-a + 2-b

  • 상단에 “내 요청 2건 반영” + ＋ 지켜볼 것 요청하기 버튼이 상시
  • 시그널 2에 ◆ 내 요청으로 잡음 배지 — 요청이 실제로 브리핑을 바꿨다는 증거
  • 2장을 다 보면 하단 링크가 버튼으로 승격(색·크기·부상)

노리는 것

진입점을 “빠져나가는 링크”가 아니라 브리핑을 키우는 행위로 바꾼다. 와쳐를 걸면 내일 브리핑이 달라진다는 루프가 화면에 보인다.

약점

상단 버튼이 강해서 브리핑 첫인상이 조금 도구스러워진다. 승격 연출은 은근해서 놓칠 수 있다.

서사 최상진입점 명확도구 냄새 약간

B3. 스레드

3-b 전면 + 2-a + 4-b

  • 브리핑 자체가 대화 스레드. 시그널이 말풍선으로 온다
  • 맨 아래가 항상 “당신 차례” — 진입점을 따로 만들 필요가 없다
  • 스레드 끝 문장이 곧 2-a 역할을 한다

챗봇으로 돌아가는 것 아닌가

아닙니다. 챗은 사용자가 먼저 말해야 비어 있지 않은 화면이 되고, 이건 아무 말도 안 했는데 이미 스레드가 차 있습니다. 매일 아침 새 메시지가 와 있는 알림 스레드에 가깝습니다.

약점

가장 과감합니다. 시그널이 늘면 스레드가 길어지고, “결국 챗 아니냐”는 오해를 살 여지가 있습니다.

D. 스코프

시그널이 목록이 아니라 장으로 있고, 그 위에 조준한다

구조

  • 가로 = 감지 시각, 세로 = 영향 규모. 좌표에 뜻이 있어서 장식이 아니다
  • 흐린 점 = 아직 패턴이 안 된 관측치. 밝은 점 = 확정된 시그널
  • 점을 고르면 우측 인스펙터가 바뀌고, 그 자리에서 바로 와쳐 걸기
  • 스캔 라인이 계속 지나간다 = 지금도 보고 있다

감시탑안의 문제를 어떻게 푸는가

  • 목록이 안 늘어난다. 시그널이 50개여도 점 50개일 뿐, 화면 높이가 안 자란다
  • 입력이 안 겹친다. 인스펙터가 별도 컬럼이라 하단 바가 캔버스 폭만 차지
  • “감지·관찰·판정” 3단은 레인이 아니라 점의 상태(흐림 → 밝음 → 링)로 표현

캐처다움

훑다가 찍는다. 사용자의 동사가 “묻다”가 아니라 “조준하다”가 된다. 빈 곳을 드래그해 범위를 지정하는 조작이 자유 질의를 대신한다.

리스크

산점도라 정확한 값 읽기가 어렵다(그건 인스펙터가 담당). 점이 겹치면 클릭이 힘들어 밀도 처리가 필요하다.
