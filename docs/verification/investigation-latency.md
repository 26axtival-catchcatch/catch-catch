## 변경 내용

`InvestigationData`는 행별 `executemany()` 대신 최대 10,000행의 JSON을 하나의 매개변수로 전달합니다.
DuckDB의 `json_transform_strict()`와 `unnest()`로 명시한 열 타입에 맞춰 적재합니다.
각 행의 누락 열을 `NULL`로 채우며 시간은 기존과 같이 UTC로 변환합니다.
파일 접근을 허용하거나 pandas 의존성을 추가하지 않습니다.
API 계약과 독립 검증의 데이터 범위도 유지합니다.
구문은 [DuckDB JSON 함수 문서](https://duckdb.org/docs/current/data/json/json_functions)와
[unnest 문서](https://duckdb.org/docs/current/sql/query_syntax/unnest)를 확인했습니다.

조사 모델에는 질의 결과를 최대 20행까지 미리보기로 전달합니다.
전체 행 수와 query ID, 다음 페이지 위치를 유지하고 전체 결과는 `read_query_result`로 조회할 수 있습니다.
측정 응답에서는 내부 query ID와 중복 SQL을 제거하고 측정 ID, 상태, 지표값, 실패 이유를 전달합니다.
서버는 원래 측정 결과와 전체 고객 집합을 보관하므로 독립 검증과 최종 집계는 그대로 수행합니다.

조사 프롬프트는 서로 독립인 조회를 한 응답에서 함께 요청하도록 안내합니다.
판정을 바꿀 수 있는 근거가 부족하면 추가 조사를 계속하며, 모델 호출 수를 강제로 제한하지 않습니다.
최종 근거에는 `query_data`에서 직접 받은 ID를 사용하도록 명시했습니다.

## 회귀 검증과 실행 반영

관련 Backend 회귀 테스트 174개를 통과했습니다.
새 테스트는 10,001행 적재, 배치 경계의 누락 열과 소수, 한글과 인용부호, UTC 시간 보존을 확인합니다.
Gemini와 Bedrock 양쪽에서 20행 미리보기 이후 전체 고객 집합과 후속 페이지를 복구할 수 있는지 확인합니다.
측정 내부 ID가 모델에 전달되지 않으면서 서버의 원래 측정 결과는 유지되는지도 검증했습니다.
기존 범위 제한, SQL 접근 제한, 독립 측정, 액티비티, Langfuse 및 API 회귀 테스트를 함께 실행했습니다.
Ruff와 변경 파일의 공백 검사를 통과했습니다.

진행 중인 분석이 없는 것을 확인한 뒤 로컬 Backend를 재시작했습니다.
선택한 환경 파일을 Python 실행 전에 전달하고 상속된 추적 환경변수를 제거했습니다.
기존 데이터 소스 경로와 모델 설정을 유지했으며 health, Swagger, OpenAPI, 소스 목록은 HTTP 200입니다.

## 증거와 재실행

측정 파일은 `data/live-validation/2026-09-10/investigator-performance/`에 있습니다.

- `baseline-metadata.json`: 기존 완료 실행과 실패 실행의 단계별 시간

- `payload-comparison.json`: 같은 도구 응답의 전달 크기 비교
