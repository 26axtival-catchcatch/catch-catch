# 검증 모델 왕복 호출 감소

검증일: 2026-09-10

동일한 합성 후보 6개와 Opus 모델을 사용한 검증에서 시간을 436.304초에서 159.234초로 줄였습니다.
모델 호출은 94회에서 22회로 줄었으며, 후보별 확정 여부는 이전 실행과 같습니다.

## 변경 내용

서버가 첫 모델 호출 전에 검증 작업의 소유권으로 `recheck_candidate`를 실행합니다.
배정 SQL의 독립 재실행, 대표 고객 여정, 지표 재측정 결과를 첫 요청에 함께 전달합니다.
필수 검사를 요청하기 위해 모델을 호출하는 단계가 사라집니다.

검증 모델에는 준비된 결과를 먼저 검토하고 부족한 근거를 한 응답에서 함께 요청하도록 지시합니다.
정상 비교군, 피드백의 고객과 의도, 사건의 시간 순서, 최종 해결 상태를 묶어 확인합니다.
성공한 검사와 동일한 여정을 반복하는 대신 집계 질의와 작업 소유의 고객 집합 테이블을 재사용합니다.
판정에 영향을 주는 의문이나 실패한 질의가 남으면 추가 조회와 수정이 가능합니다.
모델 호출 수는 고정 상한이 아니며, 이번 후보별 실측은 2~5회입니다.

준비된 결과는 실제 실행한 도구 호출과 응답 쌍으로 대화 기록에 포함합니다.
첫 호출에서는 준비된 도구 응답 전체를 전달하고, 이후에는 기존의 복구 가능한 기록 압축을 적용합니다.
질의 미리보기는 최대 20행이며 전체 결과는 서버에 보관합니다.
후보별 작업 소유권, 동시 실행 수 6개, 메시지 입력 한도 96,000바이트는 유지합니다.
Gemini와 Bedrock이 같은 실행 경로를 사용합니다.

| 지표 | 최초 단일 검증자 | 이전 후보별 검증 | 필수 검사 사전 실행 |

| 검증 시간 | 400.632초 | 436.304초 | 159.234초 |
| 모델 호출 수 | 11 | 94 | 22 |
| 전체 입력 토큰 | 1,426,346 | 2,801,795 | 572,341 |
| 단일 호출 최대 입력 토큰 | 178,822 | 38,386 | 33,804 |
| Langfuse 계산 비용 | 약 $7.64 | 약 $15.79 | 약 $3.70 |
| 판정 | 6개 확정 | 4개 확정, 2개 미확정 | 4개 확정, 2개 미확정 |

직전 코드 대비 검증 시간은 63.5%, 모델 호출은 76.6%, 전체 입력 토큰은 79.6% 감소했습니다.
최초 단일 검증자보다 호출 수는 많지만, 후보별 동시 실행을 유지하면서 검증 시간은 짧아졌습니다.
최대 메시지 크기는 94,575바이트이며, 입력 한도 초과나 모델 호출 실패는 없었습니다.
SQL 오류 1건과 최종 문서 형식 오류 1건은 같은 검증 작업 안에서 수정했습니다.

저장된 합성 입력의 검증 단계만 재생했습니다. 조사와 보고 단계에서 새 모델을 호출하지 않았습니다.
검증 시간은 첫 검증 작업 시작부터 마지막 작업 종료까지이며, 필수 검사 사전 실행 시간을 포함합니다.
데이터 준비와 trace 전송을 포함한 벤치마크 전체 실행은 178.906초입니다.
단일 사례의 실측이므로 평균 지연이나 전체 API 실행 시간의 개선율을 뜻하지 않습니다.
비용은 Langfuse의 계산값이며 AWS 청구 금액이 아닙니다.

## 판정과 회귀 검증

이전 실행과 동일한 4개 후보가 확정되고 2개 후보가 미확정으로 남았습니다.
다음 문제도 다시 확인했습니다.

- 소액결제 후보: 다른 고객군의 피드백 90건을 대상 고객의 근거로 연결한 오류
- 부가서비스 검색 후보: 정상 비교군이라고 제시한 84명이 실제 대상 고객군에 포함된 오류
- 전체메뉴 반복 후보: 81명 중 75명이 검색 전에 앱을 탐색한 시간 순서 역전과 비교군의 높은 상담 비율
- 로밍 상담 후보: 상세 1회 조회 후 상담으로 전환하여 반복 탐색을 입증하지 못한 문제

정상 비교와 SQL 의미 판단은 계속 검증 모델이 수행합니다.
필수 검사 성공만으로 자동 확정하지 않습니다.
Backend는 작업 소유의 질의, 실제 전달한 대표 여정, 최종 고객 집합과 일치하는 독립 재측정을 검사합니다.
재측정 실패 시 기존 조사자의 성공한 측정으로 확정을 대신할 수 없습니다.
단일 사례에서 판정이 일치한 것으로 일반적인 품질 동등성을 보장하지 않습니다.

관련 Backend 회귀 테스트 121개를 통과했습니다.
추가 테스트는 Gemini와 Bedrock 각각에서 준비된 근거로 모델 1회 안에 확정하는 경로와
재측정 실패를 전달받은 뒤 확정을 거부하는 경로를 확인합니다.
Ruff와 변경 파일의 공백 검사를 통과했습니다.
로컬 Backend 이미지를 다시 빌드하고 재시작했으며, 실행 중인 컨테이너의 사전 검사 코드와
Backend health, Swagger, OpenAPI의 HTTP 200 응답을 확인했습니다.

PR 준비 중 최신 `main`의 액티비티 추적 코드를 통합했습니다.
사전 검사도 검증 작업 아래의 도구 노드로 기록하며 첫 모델 호출 전에 완료 이벤트를 발행합니다.
이벤트에 SQL과 고객 ID가 노출되지 않는지 확인했고, 액티비티와 시그널 추적을 포함한 회귀 테스트 159개를 통과했습니다.
위 실측값은 액티비티 통합 전 실행의 기록입니다.
