# 03. 화면 명세

현재 구현된 여섯 화면의 구조·동작·문구입니다. **v1 문서(`docs/화면 설계서.md`)에서
바뀐 것**은 각 절 끝에 `달라진 점` 으로 표시했습니다.

---

## 1. 브리핑 (`phase: "ask"`, `?main=briefing`)

에이전트가 **묻지 않아도 이미 잡아 둔** 오늘의 시그널을 카드 덱으로 넘기는 화면입니다.
`briefing/BriefingScreen.tsx` · 데이터는 `briefing/briefing-mock.ts`.

```
 오늘의 브리핑 · 9월 8일 화요일   [내 요청 2건 반영]      [＋ 지켜볼 것 요청하기]
 두 곳에서 고객이 *멈춰 서 있어요.*
 ┌───────────────────────────────────────────────────┐
 │ 시그널 1 · 로밍 상품 결정 지연            1 / 3   │
 │ 로밍 상품을 *5.2일*씩 보다가 결정하지 못한        │
 │ 고객 *1,284명*                                    │
 │ 본문 …                                            │
 │ [가입 전환율 18.4% ▼5.7%p] [평균 탐색 5.2일 ▲…]  ╱╲╱ │
 │ [이 시그널 확인하기] [비슷한 걸 더 찾기] [넘기기] │
 └───────────────────────────────────────────────────┘
        ‹ 좌우로 드래그해 넘겨보세요 ›
 [1 · 로밍 결정 지연] [2 · 소액결제 이탈] [⊕ 더 찾기]
```

| 요소 | 설계 |
| --- | --- |
| 카드 덱 | 시그널 N장 + **"더 찾기" 마지막 한 장**. 브리핑의 끝을 빈 화면으로 두지 않는다 |
| 넘기기 | 드래그(`use-swipe-deck`) · 좌우 화살표 키 · 하단 칩 클릭 |
| 강조 | `headline`·`lede` 의 `*…*` 구간을 `Highlight` 가 마젠타 `<b>` 로 칠한다. **마크업이 아니라 문자열 규칙**이라 백엔드가 문장을 그대로 실어 보낼 수 있다 |
| 스파크라인 | `trend: number[]` (0~1) → 200×38 뷰박스 꺾은선 |
| `fromRequest` | 내 요청으로 잡힌 시그널에 `◆ 내 요청으로 잡음` 배지 |
| 요청 시트 | 상단 `＋ 지켜볼 것 요청하기` → 같은 화면 아래에 입력 시트가 열린다. 제출하면 "다음 브리핑부터 반영됩니다" 안내 |
| 지금 더 찾기 | `비슷한 걸 더 찾기` → **화면을 넘기지 않고** 아래에 대화 한 덩어리가 이어붙는다. 제출하면 그대로 `catching` 으로 |
| 하단 | 관찰 중 실험 수, 지난 브리핑 날짜 |

### 스와이프 덱 (`use-swipe-deck.ts`)

| 상수 | 값 | 뜻 |
| --- | --- | --- |
| `THRESHOLD` | 74px | 이만큼 끌면 넘어간다 |
| `SLOP` | 8px | 이 안쪽은 드래그가 아니라 클릭 |
| `FLING_MS` | 170ms | 끌던 방향으로 마저 밀어내는 시간 |

- Pointer Events 로 마우스·터치를 한 경로에서 처리합니다.
- 세로로 더 많이 움직였으면 페이지 스크롤에 양보합니다.
- 드래그로 넘긴 직후의 `click` 한 번을 `onClickCapture` 로 삼킵니다.

### 브리핑을 기본으로 전환할 때

1. `use-catch-session.ts` 의 `const DEFAULT_MAIN: MainScreen = "ask"` → `"briefing"`
2. 그것뿐입니다. 셸이 `options.main` 으로 갈라 렌더합니다.

전환 판단 기준: 브리핑 시그널이 **실제 백엔드 데이터로** 채워지는지. 목업 2건 고정인
상태로 메인에 올리면 "매일 도는 서비스"라는 주장이 데모에서 무너집니다.

> `달라진 점` — v1 에는 없던 화면입니다.

## 2. 질문하기 (`phase: "ask"`, 기본)

`ask/AskScreen.tsx`

```
              고객은 말보다 먼저 신호를 보냅니다
            고객의 시그널을 찾아보세요            ← Gasoek One
                  [데이터셋 5] [최근 14일]
    ╱╲╱╲╱  ┌────────────────────────────────┐  ╱╲╱╲╱
    시그널 │ (+)  질문 입력…            (🔍) │  시그널
    ╱╲╱╲╱  └────────────────────────────────┘  ╱╲╱╲╱
   [AI검색 기획] [AI검색 기획] [CX] [CRM]      ← 제안 카드 4장
```

| 요소 | 설계 |
| --- | --- |
| 좌우 시그널 파형 | 입력창 **바깥** 좌우로 같은 파형이 흐른다. 두 칸이 마스크 방향만 반대라 하나의 신호가 입력창을 지나가는 것처럼 보인다 |
| 입력 중 | `data-typing` — 입력이 이어지는 동안만 진폭이 커진다. 멎으면 `IDLE_MS = 1400` 뒤 가라앉는다 |
| 전송 | `data-sending` — 파형이 입력창으로 빨려 들어간 뒤(`SEND_MS = 420`) 화면을 넘긴다. `prefers-reduced-motion` 이면 즉시 전환 |
| Placeholder | `TypewriterPlaceholder` 가 페르소나별 질문을 타자 치듯 교체. **실제 `placeholder` 속성이 아니라 오버레이** (속성을 계속 바꾸면 스크린리더가 매 글자를 다시 읽는다). 한 글자라도 입력하면 즉시 사라짐 |
| 입력창 | `textarea` 1행에서 자동 높이 증가. `Enter` 제출, `Shift+Enter` 줄바꿈 |
| `+` 버튼 | 2depth 컨텍스트 메뉴 `ComposerMenu` |
| 제안 카드 | 페르소나 태그 + 라벨 + 질문 전문. `suggestedQuestions` 가 있으면 그것으로 대체되고 태그는 `추천` |
| 안내 박스 | 범위 밖 질문으로 되돌아왔을 때. **경고색이 아니라 브랜드 톤** — 오류가 아니라 에이전트의 안내다 |

### 조건 메뉴 (`ask/ComposerMenu.tsx`)

| 패널 | 내용 |
| --- | --- |
| root | `데이터셋 ›` / `기간 ›` |
| 데이터셋 | 연결된 소스가 **전부 켜진 상태**로 시작. 소스별 설명·주제 뱃지·보유 기간. `search_history` 는 `REQUIRED_SOURCE` 라 해제 불가 |
| 기간 | 칩(최근 7/14/30일) + **직접 선택**(date input). `DATA_RANGE` 밖은 선택 불가 |

- 기준일 `DEMO_TODAY = 2026-08-19`. 칩은 이 날짜에서 역산합니다.
- `Escape` — 하위 패널에서는 root 로, root 에서는 닫기. 바깥 클릭은 닫기.

`달라진 점` — 입력창 좌우 시그널 파형과 전송 흡입 연출이 추가됐습니다(v1 에 없음).

## 3. 캐치하는 중 (`phase: "catching"`)

`catching/CatchingScreen.tsx`

```
        최근 로밍을 알아보는 고객들이 가장 많이 궁금해하는 게 뭐야?   ← 질의 바

   [분석 3/5]  ━━╱╲━━╱╲━━╱╲┈┈┈┈┈┈           도구 5 · 포착 2
   ◌ 시그널을 캐치하고 있어요

   ∑  AI검색 이력에서 로밍 검색을 모으는 중            12,480건
   ◑  같은 주제를 반복 검색한 고객을 추리는 중            328명
   ◈  포착 · 반복 검색 3.4회  328명이 같은 주제를 …
   ⇄  앱 행동로그를 고객 단위로 잇는 중                 1,204건
```

**심박 라인이 곧 스테퍼입니다.** 별도 스텝 인디케이터를 두지 않습니다.

| 요소 | 설계 |
| --- | --- |
| 질의 바 | 질문은 콘텐츠가 아니라 맥락이므로 중앙 스택에서 빼 상단에 고정 |
| 심박 (`SignalProgress`) | 단계 하나 = 박동 하나. 끝난 구간은 마젠타로 남고, 진행 중 구간은 그 단계 소요시간(`STAGE_DURATIONS × speed`)에 맞춰 `stroke-dashoffset` 으로 그려진다. 남은 구간은 회색 평선 |
| 배지 | `{현재 단계 short} {n}/5` |
| 카운터 | `도구 N · 포착 N` — 지금까지 부른 도구와 확정된 사실의 수. 실행 중이라는 증거 |
| 진행 레일 | 최근 `RAIL_WINDOW = 9` 줄. 위쪽은 마스크로 흐려지며 사라진다. 현재 줄은 `data-now` |
| 멈춤 | `flatline` · 실패 · 심문 대기 시 심박이 평선으로 떨어지고 레일 끝에 `⏸` 줄이 붙는다 |
| 완료 | `HeartBurst` — 마젠타 플래시 → 하트 → "찾았다!" (`BURST_MS = 1000`) |

### 진행 문장의 네 종류

`state/tick-marks.ts` 가 기호를 붙입니다. **로딩 화면과 결과 화면의 과정 보기가 같은
기호를 써야** 나중에 "아까 그 줄"로 알아볼 수 있습니다.

| `kind` | 기호 | 뜻 | 화면 표현 |
| --- | --- | --- | --- |
| `think` | `✎` | 모델이 판단한 문장 | 문장만 |
| `tool` | primitive별 기호 | primitive 호출 | `<code>이름</code>` + 우측에 결과 요약(`meta`) |
| `fact` | `◈` | 확정된 사실 | `포착 · {short}` 배지 |
| `reject` | `✕` | 근거 부족으로 버린 주장 | `근거 부족` 배지 |

primitive 기호: `catalog_sources ⌘` · `aggregate_events ∑` · `build_segment ◑` ·
`match_sequence ⇄` · `profile_customers ◎` · `validate_claims ✓`

### 단계별 체류 시간 (`STAGE_TICKS[].ms` 합)

| 단계 | 문장 수 | 시간 | 성격 |
| --- | ---: | ---: | --- |
| 목표 | 3 | 1.30초 | 훑는 속도 |
| 계획 | 2 | 0.86초 | 훑는 속도 |
| 분석 | 7 | 3.20초 | 도구가 후루룩 |
| 인사이트 | 3 | 2.42초 | 읽는 속도 |
| **검증** | 3 | **3.70초** | 마지막 문장 혼자 **1.7초** |

합계 **11.48초**. 앞 세 단계 47%, 뒤 두 단계 53%.
데이터를 훑는 구간은 기계 속도로 흘리고 결론과 검증만 잡아 둡니다.
**비율을 바꿀 때 검증 마지막 문장이 1.5초 아래로 내려가지 않게 합니다** — 우리 팀
차별점이 드러나는 문장입니다.

### 심문 모달 (`clarification`)

진행이 멎은 순간을 약점이 아니라 **단서를 좁히는 장면**으로 연출합니다.

1. 심박이 평선으로 떨어지고 화면이 어두워짐
2. 에이전트 질문이 타이핑되며 등장 (`TYPE_MS = 32`, 첫 화면 placeholder 와 같은 모션 언어)
3. `>` 프롬프트 + 모노 입력창 + 빠른 답변 버튼 2개
4. 답변 전송 → `answerClarification()` → 남은 단계 재개

- 헤드라인 `잠깐, 하나만 더 확인할게요`, 태그 `단서를 좁히는 중`
- 브라우저 기본 `alert`/`confirm` 금지. **focus trap 을 건 커스텀 dialog**
- 백엔드가 답을 기다리므로 "나중에 답하기"·닫기 버튼을 두지 않음

### 실패 (`outcome: "failed"`)

**화면을 자동으로 바꾸지 않습니다.** 자동으로 첫 화면에 돌려보내면 사용자가 왜
돌아왔는지 알 수 없습니다.

- `연결 끊김` 배지 + 사유(`failureReason`) + 안내 문구
  ("질문과 조건은 그대로 두었어요. 다시 캐치하면 멈춘 지점부터 이어서 분석합니다.")
- `[다시 캐치하기]` `[질문 바꾸기]`
- 모달로 덮지 않습니다. 평선을 가리기 때문입니다.

`달라진 점` — v1 의 "크레딧처럼 흐르는 로그"가 **기호가 붙은 레일**로 바뀌었고,
도구·포착 카운터가 추가됐습니다. 총 소요는 10.9초 → 11.48초.

## 4. 캐치 결과 (`phase: "result"`)

`result/ResultScreen.tsx`. **탭이 아니라 한 흐름의 세로 스크롤**입니다.

```
 [부분 캐치]                                   ← degraded 일 때만
 단기 일본 여행 로밍을 고르지 못한 고객
 328명을 찾았어요                              ← Gasoek One, 숫자만 마젠타
 데이터 2026.08.05 – 2026.08.19 · 분석 2026.08.19
 (이 분석 이후 ~를 적용해 관찰 중이에요. 아래 수치는 적용 전 시점의 값입니다.)
 요약 문단…
 [시그널 고객 328명] [평균 반복검색 3.4회] [상세조회후 미가입 71%] [재검색까지 4.2일]
 ── 고객 여정 맵 ────────────────────────────
 ── 검증된 발견 │ 다음 행동 ──────────────── (2열)
 ── 이 결론이 나온 과정 보기 ▾ ──────────────
 [새로 캐치하기]
```

| 블록 | 내용 |
| --- | --- |
| 헤드라인 | `{headline}` + `{headlineCount}명을 찾았어요`. `headlineTrailer` 가 있으면 아래 한 줄 |
| 부분 캐치 배지 | `outcome === "degraded"` 일 때. 누르면 `limitations` 펼침 |
| 스냅샷 | `데이터 {periodLabel}` · `분석 {analyzedAt}`. **리포트를 사후에 갱신하지 않으므로 시점을 못 박는다** |
| 이후 변화 | 실험이 있으면 "적용 전 시점의 값"임을 알리고 실험으로 가는 링크 |
| 지표 카드 | `value` 가 `NaN` 이면 숫자를 지어내지 않고 **점선 테두리 + "근거 부족"** |
| 고객 여정 맵 | `JourneyFlow` (§4.1) |
| 검증된 발견 | `findings` 중 **`verdict === "passed"` 만**. 각 문장에 근거 칩 → 드로어 |
| 다음 행동 | `actions`. 실험이 있으면 진행 바와 상태 문구. `keywords` 가 있는 항목만 `미리보기` / `경과 보기` 버튼, 나머지는 `다음 단계` 라벨 |
| 과정 보기 | `ProcessTrace` (§4.2) |

### 4.1 고객 여정 맵 (`result/JourneyFlow.tsx`)

```
 ▶ ━━━━━━━━━━━━━●━━  9/14
 ┌──────────────────────────────────────────┐
 │        8/12  8/12  8/12 …  8/18          │
 │ AI검색        ●───●          ●           │
 │ 검색 피드백          │   ●               │
 │ 앱 행동    ●──┘      └───●               │
 │ 가입 정보     └──●            ●          │
 │ 상담                       ●             │
 │ 시그널 강도 ╱╲╱╲╱───                     │
 └──────────────────────────────────────────┘
 8/18 14:23  "며칠짜리 로밍을 써야 할지 모르겠어요"  6일간의 자가 탐색 끝에 …
```

- **격자는 스윔레인, 그 위를 선 하나가 시간순으로 관통**합니다. 레인을 넘나드는
  지그재그가 곧 cross-channel 이라는 주장의 시각적 증거입니다.
- 열은 날짜가 아니라 **이벤트 순서**(`column`)입니다. 선이 항상 왼쪽에서 오른쪽으로 흐릅니다.
- `▶` 재생(`PLAY_MS = 700`) — 노드가 시간순으로 켜지고 연결선이 `stroke-dashoffset` 으로
  그려집니다. 스크러버로 임의 지점 이동 가능.
- **노드를 누르면 곧바로 원본 근거 드로어가 열립니다.** 사이에 상세 패널을 두지 않습니다.
- 하단 강도 곡선은 `JourneyNode.intensity` 기반입니다. 감정 곡선처럼 지어낸 값을 쓰지 않습니다.
- 재생 중 현재 지점은 화면 아래 **한 줄 캡션**으로만 읊습니다 (`aria-live="polite"`).

> 디자인 씽킹 유저 저니맵의 감정 격자는 채택하지 않습니다. 칸을 채우려면 데이터에
> 없는 값을 지어내야 하고, 이는 "모든 주장은 원본 데이터로 검증된다"는 원칙과 충돌합니다.

`tone` 값: `signal`(기본) · `repeat`(반복·헛걸음) · `negative`(불만·이탈) · `resolved`(해결).

### 4.2 과정 보기 (`result/ProcessTrace.tsx`)

**분석가 모드 토글을 대체한 블록입니다.** 접혀 있고, 열면 로딩 때 흘러간 과정을
같은 기호·같은 문장으로 다시 폅니다.

```
 이 결론이 나온 과정 보기        5단계 · 도구 7회 · 포착 4건 · 18.4초   ▾
 ───────────────────────────────────────────────────────────────
 run_id run_20260819_1042_7f3ac9 · dataset synthetic-20260819
 ① 분석 목표를 세우고 있어요            goal_created
     ✎ 질문의 의도를 해석하고 있어요
     …
 실행한 분석 스텝
   S1  로밍 관련 검색 이력 집계   aggregate_events  1.8초
   S4  앱 행동과 가입 상태 대조   match_sequence    4.2초
       계획 수정됨 — S4 (rev 1: 가입 상태 미포함)
 [주장별 근거 계보 보기 →]  [Langfuse 트레이스 ↗]  [Datadog LLM Observability ↗]
```

- 요약 줄의 수치는 `STAGE_TICKS` 에서 **계산**합니다 (도구 7회 · 포착 4건).
- `Stage.event` 를 `<code>` 로 노출합니다. 화면에 Canonical Run Event 이름이 그대로 보입니다.
- `planSteps[].revisedFrom` 이 있으면 "계획 수정됨"을 노출합니다. **감추지 않습니다** —
  스스로 계획을 고치는 에이전트라는 증거입니다.
- 외부 링크는 `observabilityLinks(runId)` 가 만듭니다 (Langfuse · Datadog).

### 4.3 근거 드로어 (`result/EvidencePanel.tsx`)

Tier 2. 결과 화면을 떠나지 않고 원본 한 건까지 확인합니다.

- 요약 · 데이터 원천 · 발생 시각 · 마스킹된 고객 ID · **원본 필드 표**
- 하단에 "고객 식별자는 마스킹된 값이고, 데이터는 모두 합성입니다"
- `Escape` 로 닫기. 스크림 클릭으로 닫기. `Overlay` portal 필수.
- 없는 근거 ID 면 "이 근거는 아직 불러올 수 없어요"

`달라진 점` — v1 의 **탭 3개와 기본/분석가 모드 토글을 폐기**하고 한 흐름으로 합쳤습니다.
여정 맵의 우측 상세 패널도 폐기하고 노드 클릭 → 근거 드로어 직행으로 바꿨습니다.
`ProcessTrace`, 스냅샷 시점 표기, 실험 맥락 알림, 외부 트레이스 링크가 새로 생겼습니다.

## 6. 액션 (`phase: "action"`)

`action/ActionScreen.tsx`. 한 페이지가 세 단계로 변신합니다. **페이지를 옮기지 않아
서사가 끊기지 않습니다.**

```
① preview   AS-IS ↔ TO-BE 시안 · 예상되는 변화 표 · [✨ 캐치한 대로 바꿔보기]
              └ 진입 시 1.9초 매직 연출 (applying 은 별도 단계가 아니라 preview 안의 상태)
     ▼ onApply()
② watching  "적용 후 N일째" · 스파크라인 3개 · [⏩ 7일 뒤로 감기] → 420ms/프레임
     ▼ 마지막 프레임
③ report    "예측 6개 중 4개가 맞았어요" · 스파크라인 + 채점 표 · AI 인사이트 · [다음 액션]
```

단계는 `stageOf(experiment)` 가 결정합니다 — 실험이 없으면 `preview`, `watching` 이면
`watching`, `done` 이면 `report`. **새로고침해도 실험 상태에서 복원됩니다.**

### 6.1 세 단계가 같은 데이터를 다르게 그린다

| 단계 | 표현 |
| --- | --- |
| 미리보기 | **표** — 지표 · 지금 · 예상 · 변화 (관측값이 없으므로 표만) |
| 관찰 중 | **스파크라인** — 큰 숫자 · 델타 · 추이 · 목표 점선 (재생 위치까지) |
| 리포트 | 스파크라인(끝까지) + **채점 표** |

역할이 겹치지 않게 나눕니다 — **스파크라인은 추이(gain 3개), 표는 채점(6개 전부).**
큰 숫자 · 델타 · 스파크라인은 Datadog·Grafana·Amplitude·Stripe 가 모두 쓰는 형태라
설명 없이 읽힙니다. 목표는 **점선 한 줄**이고, 값이 그 선을 넘었는지가 한눈에 읽힙니다.

> 진행률 트랙(시작→목표 사이 위치)은 폐기했습니다. 그건 지표 추이가 아니라 프로젝트
> 진행률 UI 이고, 7일치 시계열을 한 점으로 뭉갭니다.

### 6.2 좋아질 것 / 나빠질 수 있는 것

**좋은 것만 실으면 검증하지 않은 제안과 구분되지 않습니다.** `direction` 이
`gain` / `risk` 로 갈리고 둘을 **같은 모양으로** 싣습니다. 각 예측에 근거와 이유가 붙습니다.

| direction | 표현 | 예 |
| --- | --- | --- |
| `gain` | 무채색 | 가입 전환율 12% → 18% |
| `risk` | 앰버 좌측 바 · `이건 나빠질 수 있어요` 구획 | 다른 로밍 상품 노출 -23% |

`gain` 을 마젠타로 칠하면 TO-BE 시안의 마젠타와 경쟁해 둘 다 죽습니다.

### 6.3 판정은 빗나간 쪽만 강조

적중은 기대대로이므로 조용합니다. **시선은 빗나간 예측으로 가야** "숨기지 않는다"가
읽힙니다. `miss` 행만 사유가 지표명 아래 붙고 앰버로 칠합니다.

### 6.4 시안은 실제 구조를 따른 와이어프레임

픽셀까지 재현하지 않습니다. 실제와 조금만 달라도 거짓이 되고, 디테일이 많아지면
**무엇이 바뀌었는지가 묻힙니다.** 대신 **배치는 실제 구조를 그대로** 따릅니다 —
AI검색은 답변이 위, 입력창이 하단, 추천검색어가 입력창 바로 위입니다.
시안 아래에 "실제 화면 구조를 따른 와이어프레임입니다"를 명시합니다.

매직 연출(`INTRO_MS = 1900`): 마젠타 빛줄기(`sweep`)가 TO-BE 를 좌→우로 훑고, 지나간
자리에 새 항목이 `--order` 순서로 하나씩 그려지고, AS-IS 는 흐려지며 물러납니다.
`다시 보기` 버튼으로 재생할 수 있습니다.

### 6.5 타임랩스는 데모용임을 숨기지 않는다

`⏩ 7일 뒤로 감기` 아래에 그대로 적습니다.

> "실제로는 7일을 기다려야 하지만, 데모를 위해 미리 준비한 데이터로 감아 볼게요."

숨기면 속이려 한 것처럼 보이고, 밝히면 여기까지 설계했다는 뜻이 됩니다.
검증 기록에서 `dataset_version: synthetic-…` 을 당당히 노출하는 것과 같은 태도입니다.

### 6.6 AI 인사이트는 스파클로 구분

리포트 마지막 해석 문장은 측정된 수치가 아니라 **AI 가 만든 문장**입니다.
`Sparkle` 마크를 붙이고, 이 화면에서 **면을 갖는 유일한 블록**으로 둡니다.
스파클은 **AI 산출물과 AI 실행 버튼에만** 씁니다.

### 6.7 빗나간 예측이 다음 액션을 정당화한다

```
액션1(추천검색어) 적용 → 예측 상담 인입 -37% / 실제 -22% ← 빗나감
   → "검색은 줄었지만 상세페이지에서 여전히 이탈했습니다"
   → 액션2(기간 선택 가이드)가 필요한 이유가 데이터로 증명됨
```

`nextActionId` 로 결과 화면의 해당 카드로 돌아가 `highlightActionId` 로 표시합니다.

### 6.8 실험 겹침 경고

`conflictOf(segmentLabel, actionId)` 가 같은 세그먼트를 관찰 중인 실험을 찾으면 적용
직전에 모달로 알립니다.

> **겹치는 실험이 있어요** — 같은 고객군(`{segmentLabel}`)을 이미 관찰 중이에요.
> 지금 함께 적용하면 지표가 움직여도 **어느 쪽 효과인지 구분할 수 없어요.**
> `[그래도 함께 적용]` `[진행 중인 실험 먼저 보기]`

막는 게 아니라 알리고 사용자가 정합니다. 세그먼트가 다르면 경고 자체가 뜨지 않습니다.

### 6.9 액션 하나만 깊게

`ACTION_PLANS` 에는 `search_keyword` 하나만 있습니다. 셋을 다 만들면 전부 얕아집니다.
나머지 둘은 결과 화면 카드로 두고, 리포트 마지막에서 액션2 로 이어지는 고리만 만듭니다.

### 6.10 진입점은 둘, 목록 화면은 없다

| 진입점 | 성격 |
| --- | --- |
| 상단 바 `● 관찰 중 N` 배지 (`ExperimentMenu`) | 전역 접근. 상단 바는 phase 와 무관하게 항상 렌더된다 |
| 결과 화면 액션 카드 | 그 분석 안에서의 상태 |

배지는 실험이 있을 때만 나타나고 없으면 자리도 차지하지 않습니다.
별도 목록 화면은 만들지 않습니다.

## 7. 시연 스캐폴딩 (백엔드 연결 시 제거)

URL 스위치로 엣지케이스를 그대로 재현합니다. 대부분 `use-catch-session.ts` 한 파일에 모여 있습니다.

| 파라미터 | 용도 |
| --- | --- |
| `?main=briefing` / `?main=ask` | 첫 화면 전환 |
| `?pause=goal\|plan\|analyze\|insight\|verify\|complete\|clarify` | 로딩 화면 정지 |
| `?speed=0.25~3` | 전체 진행 속도 배수 |
| `?burst=lens` | 완료 마크를 돋보기로 |
| `?clarify` `?degraded` `?failed` `?unsupported` | 엣지케이스 재현 (값 없이 붙여도 켜짐) |

엣지케이스 플래그를 붙이면 질문 입력 없이 **자동 실행**됩니다.

### 지우면 안 되는 것

| 항목 | 이유 |
| --- | --- |
| `?view=result\|trace\|action` | **실제 기능.** 새로고침 복원 · 뒤로가기 · 링크 공유 |
| `restore()` · `syncUrl()` | 위와 한 몸. Mock 대신 API 호출로 내용만 교체 |
| `retry()` | 실패 후 재시도. 사용자 기능 |
| `TypewriterPlaceholder` 의 `paused` | 이름만 비슷할 뿐 시연과 무관 |
| `Stage.event` · `StageTick.meta` | 백엔드 매핑 참고값 |

### 삭제 순서

`useDemoOptions()` 를 먼저 지우면 나머지가 전부 타입 에러로 드러납니다.
에러를 따라가며 지우면 빠짐없이 정리됩니다. (`flags` · `pause` · `speed` · `burst`,
`freeze()`, `suppressFlags`, 자동 시작 effect, `CatchingScreen` 의 `burstMark`/`speed` prop)
