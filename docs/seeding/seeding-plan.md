왜 이걸 골랐나?

근거는 즐겨찾기 설정 횟수 데이터. 앱 즐겨찾기 설정 순위에서 부가서비스 조회/해지가 846건으로 2위. 1위 영화예매는 곧 오픈 예정이라 데이터 변경 가능성 있으므로 제외.

또한 개선안이 명확 (AI검색)

AI검색이 현재 이 메뉴로 CTA 안내를 잘 하고 있어서 개선 효과가 명확함

해지, 요금 같은 민감 소재가 아니라 VAS라서 가데이터에 대한 공격을 덜 받을 수도.

가설

즐겨찾기를 많이 설정한다 = 그 메뉴를 찾기 어렵다. 한 번 고생해서 찾은 뒤 다신 헤매지 않으려고 등록한다는 것.

부가서비스가 높게 나온 이유는 두 가지로 추정한다.

가입정보 관리 하위에 있어서 위치를 예상하기 어려움

유무료 부가서비스 가입/변경/해지 니즈 자체가 많음

가설이 맞는지는 실제 데이터를 연결했을 때 에이전트가 판단할 몫이므로,, 우리가 검증할 건 가설이 아니라 이런 구조가 동작하는지를 보는 것.

헤맴 세션 조건을 모두 만족하게 생성. 한 세션에서 서로 다른 메뉴 3개 이상 진입, 각 체류 5초 미만, 같은 상위 메뉴로 2회 이상 되돌아옴, 세션당 총 체류 60~180초

오답경로는,
고객이 부가서비스가 있을 거라 착각하는 위치를 경로에 심는다. 아래 패턴을 섞어 사용
· 마이 → 요금제 조회/변경 → 뒤로 → 멤버십 → 뒤로 → 가입정보 → 부가서비스 (도달)
· 마이 → 요금/납부 → 뒤로 → 데이터 충전 → 뒤로 → 이탈
· 홈 → 전체메뉴 → 마이 → 요금제 → 뒤로 → 전체메뉴 → 이탈
미도달 이탈 고객은 마지막 화면을 전체메뉴 또는 마이 홈으로

즐겨찾기 설정 이력은,
부가서비스 조회/해지를 최상위권 건수로 배치. 설정 직전에 반드시 헤맴 세션이 선행하게 생성 (탐색 3~5회 → 도달 → 설정). 대조군으로 요금/납부 조회는 탐색 없이 바로 설정되게

AI검색 이력

의도별로 검색어를 나눠 생성
· 해지: 부가서비스 해지, 부가서비스 끄기, 안 쓰는 서비스 빼기, 유료 부가 해지
· 조회: 내가 가입한 부가서비스, 부가서비스 확인, 뭐 가입돼있지
· 변경: 부가서비스 변경
같은 고객이 표현만 바꿔 2~4회 반복. 간격은 같은 세션 내 또는 1~7일 후로 분산. has_cta는 다수를 false로

AI검색 피드백

부정 피드백 사유를 "답변은 맞는데 이동 방법을 모르겠음" 계열로 집중. 부정 피드백 고객은 이후 앱 헤맴 또는 상담으로 이어지게

상담 이력

상담 시각은 앱 이탈 시각보다 이후. 요약에 "어디서 해지하는지 모르겠다", "메뉴를 못 찾겠다" 계열 문장을 명시적으로 포함. resolved_by는 대부분 "상담원 처리"

고객 기본정보

헤맴 고객군에 공통 특성 부여. 부가서비스 3개 이상 가입, 가입 기간 24개월 이상. 노이즈 고객은 이 조건에 걸리지 않게 분산

케이스 2. 소액결제 한도 변경 중도 이탈

왜 이걸 골랐나

상담 데이터와 화면 구조. 소액결제 한도 관련 불만 콜과 한도 변경 시도 내역이 많다는 점에서 출발.
(제 사례도 있음)

실제 화면을 보면 한도 슬라이더를 조작하고 손을 떼는 순간 동의 바텀시트가 즉시 올라오게 됨. → 사용자가 의도한 동작(값 조정)과 시스템 반응(약관 동의 요구) 사이에 간격이 있어서, 놀라서 닫고 다시 시도하는 패턴이 생길 수 있다.

추가로 케이스 1과 문제 유형이 다르다는 게 선정 이유.

케이스 1: 못 찾음 → 추천질문 추가로 즉시 해결 가능

케이스 2: 찾았는데 못 끝냄 → 화면 개선이 필요하므로 담당팀 전달까지

한 가지 논의포인트. 에이전트가 "UI가 문제다"라고 단정하지 않게 해야할지? 데이터로 말할 수 있는 건 이탈이 특정 단계에 집중된다는 것까지. 원인 판단과 개선 설계는 사람이 하는게 맞을수도 있고, 예민한 부분이 있을 수 있다.

재시도패턴
같은 고객이 하루 또는 며칠 내 2~4회 재시도, 매번 같은 지점에서 이탈. 정상 완료 고객도 일부 포함해 대조군 확보

한도 변경 이력
같은 고객이 하루 또는 며칠 내 2~4회 재시도, 매번 같은 지점에서 이탈. 정상 완료 고객도 일부 포함해 대조군 확보

AI검색 이력

의도별로 검색어를 나눠 생성
· 방법 문의: 소액결제 한도 늘리기, 결제 한도 변경, 한도 올리는 법
· 실패 후 재검색: 한도 변경 안 됨, 결제 한도 변경 오류, 한도 변경 왜 안돼
· 차단/축소: 소액결제 차단, 결제 한도 0원
핵심: 앱 이탈 직후에 검색이 발생하게 배치한다. 화면에서 막힌 뒤 검색으로 넘어온 순서가 보여야 함. 같은 고객이 표현을 바꿔 2~3회 반복

AI검색 피드백

부정 피드백 사유를 "안내대로 했는데 안 된다", "설명이 실제 화면과 다르다" 계열로 집중. 답변 내용 자체는 틀리지 않았는데 화면에서 막혀서 해결이 안 되는 상황을 나타냄. 부정 피드백 이후 재시도 또는 상담으로 이어지게

상담 이력

상담 시각은 마지막 이탈 시각보다 이후. 요약에 한도 변경 관련 불만, 변경이 안 된다는 문의 포함. 카테고리는 소액결제 한도로 통일

소액결제 정보

미완료 고객군에 공통 특성 부여. 소액결제 이용 이력 있음, 현재 한도가 기본값(15만원) 상태 유지. 연령대는 특정 구간에 쏠리지 않게 분산하되 대조군(정상 완료)과 구분되는 특성이 하나는 나오게
